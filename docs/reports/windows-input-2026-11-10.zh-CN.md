# v0.5.1 输入与设置验证

本轮修复 UTF-16、UTF-32 文件导入后中文损坏，以及并发保存独立配置项时丢失更新的问题。文件上限统一在解析入口检查，路径读取限制为上限加一个字节，缓存摘要按增量计算。解析缓存版本升级后会重新解析旧记录。

## 验证

- UTF-8、UTF-8 BOM、UTF-16 和 UTF-32 的大小端 BOM 样例原文均保留。损坏字节、截断编码及空字符文本被拒绝。未带 BOM 的旧编码文件需要另存为 UTF-8。
- 四个独立数据库连接并发更新调用预算、历史保留、缓存保留和复核输出上限，连续四组修改均保留。无效设置提交后原记录保持完整。
- 完整源码自检、评测器自检与界面交互回归通过。
- 打包 EXE 经文件路径读取 UTF-16 中文文本，由北邮 `deepseek-v4-flash` 规划、执行、独立复核。输入为上午领取 17 份、下午领取 28 份、退回 3 份，实际返回 42，验收通过。共 3 次云端调用、1,438 token，本地模型调用为 0。历史查询和重复提交复用通过。
- 独立 EXE 回归确认 UTF-16 文件上传与缓存、损坏文本拒绝、查表、静态代码求值、任务恢复、预算与历史持久化、重复启动保护、重启和退出。OCR 推理跳过。
