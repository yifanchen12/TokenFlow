# 仓库问答质量基线 — v0.4.0

[English report](repository-quality.md) · [逐样本结果](repository-quality.json) · [样本集](../../eval_cases.repository.json)

## 范围与方法

评测于 2026-10-04 使用本地 Ollama `qwen3.5:9b` 完成。样本集包含针对 10 个公开仓库文件编写的 60 个事实问答，每题均有明确答案及原文中的关键事实标注；不含私人文档或真实业务任务日志。

将原始内容和 TokenFlow 实际选中的处理后提示词交给同一模型。通过 Ollama 原生聊天接口设置 32,768 Token 上下文、温度 0、关闭思考、输出上限 128 Token；逐题交替原文与处理后的请求顺序。答案采用规范化后的精确匹配，允许显式列出的答案变体，不以数字子串命中判为正确。

报告中的来源哈希均已与最终测试文件核对；最大输入用量加输出预留未超过配置的上下文。下列输入及总 Token 数由 Ollama 报告，与 TokenFlow 的提示词大小估算分开记录，不等同于计费金额。

## 结果

| 指标 | 原文 | TokenFlow 选中提示词 |
|---|---:|---:|
| 完成的成对样本 | 60 | 60 |
| 答案正确 | 60/60（100%） | 60/60（100%） |
| 完整保留标注事实 | 60/60 | 60/60 |
| 模型报告的输入 Token | 184,031 | 135,866 |
| 模型报告的总 Token | 184,296 | 136,131 |
| 请求耗时中位数 | 2,211 ms | 1,172 ms |

全部 60 题的输入 Token 减少 **26.17%**。其中 30 题实际采用压缩，另外 30 题保留原文。通过的样本集门槛为：至少完成 50 对、标注事实零丢失、处理后正确率至少 90%、正确率下降不超过 2 个百分点、输入 Token 至少节省 5%。缺少用量或存在未完成样本均不能通过。

首次离线检查发现 11 题丢失标注事实。将命中行扩展为完整 Python 函数、Markdown 章节或文本段落，并在超出预算时回退原文后，最终离线检查丢失数为零。这是事实保留的前后对比，不是模型正确率提升的前后实验证明。

## 结论与限制

本次运行说明：**仅在这组仓库问答中**，输入用量下降且答案正确率没有下降。不能据此宣称真实业务质量已获证明、任意文档均不丢信息，或较旧版存在因果性的正确率提升。题目以简短、可核验的事实为主，未覆盖复杂推理、OCR、长文综合和冲突证据。该语料参与指导抽取修复，并非用于验证泛化的独立留出集。

耗时仅供描述，不构成受控性能结论：模型缓存已预热，原文与处理后请求交替进行，部分评测期间同时执行了 EXE 打包。未测量货币成本或云端服务商表现。中文哈希检索及数据库迁移验证独立于本答案评测。

下一轮领域测试应使用独立标注的留出任务并保持同模型成对评测。评测报告可能包含模型答案和文档事实，公开前必须审查。

## 复现

将 `TOKENFLOW_OLLAMA_URL` 配置为本地 Ollama 的 OpenAI 兼容端点，然后运行：

```powershell
python eval_workflow.py --cases eval_cases.repository.json --provider ollama --model qwen3.5:9b --max-tokens 128 --ollama-context 32768 --report tmp/repository-model.json --enforce-gate
```

此命令发出 120 次模型请求。更换源码版本、模型构建或运行环境可能改变结果。公开 JSON 包含每题来源 SHA-256、原文及处理后答案、用量、耗时、评分和门槛，不包含私人网关地址或凭据。
