# 端云协同分配与体验验证

日期：2026-10-20。依据已确认的 [端云协同方案](../plans/edge-cloud-task-experience.md)。用户澄清后，本轮优化协同调度和体验；先前专用 Python 编译方案留作后续场景，没有新增任意命令执行权限。

## 已完成的行为

- 工作台提供端云协同、仅本地、按高级角色配置三种策略。简化连接设置可以分别选择端侧整理与复杂任务模型，将复杂连接应用到规划、执行和验收；需要不同模型时仍可展开高级分配。新配置默认协同，已有设置未指定新字段时保留原角色分工。
- 受保护的 `POST /api/tasks/preview` 只检查分工与配置，不调用模型。启动自动再检查。文件资料读取后再判断实际所需模型；纯统计和查表无需模型。端侧未配置时说明本地程序整理后的处理路径。
- 连接实际位置依据登记信息显示为端侧、云端或原生执行器。原生工具内部位置无法确认时明确标注，分类摘要角色可以是历史上显式配置的云端连接，不能仅因角色名就算成本地推理。
- 新计划声明步骤编号、前置依赖、输入范围和预期产出。仅向步骤传递它要求的原资料及依赖输出，最多四步顺序执行；拒绝越序/循环、重复编号、空依赖交接和未汇总必要产出的计划。旧格式计划继续按原依赖语义读取。
- 端侧步骤实际调用失败后，每步最多向配置的复杂执行器升级一次，先检查后续调用名额、上下文和验收 Token 预留。没有预算、仅本地策略、云端失败等情况保留已完成步骤。失败调用仍记账，中间结果明确标为部分结果。
- 最终验收仍读取原文，保持原有一次有证据修正。界面显示实际分工、依赖、阶段状态、耗时、升级原因和各步产出；刷新、取消、历史切换与旧记录兼容。
- 最终审查补充两个边界：从显式云端整理角色改为本机连接时，不把云端模型名带到本机连接；新格式统计步骤只读取原资料，不冒充对中间文本的任意计算。
- 评测报告记录策略、步骤、实际位置与升级；同模型对照明确使用原角色模式。原有价格口径和密钥存储不变，未获得完整用量时不增加虚构的累计节省。

## 真实模型端云流程

实际使用本机 Ollama `qwen3.5:9b` 与已有原生 Codex 配置；每次调用记录的原生模型为 `gpt-6-luna`，没有为测试切换日常模型或写入新云端密钥。本机服务先检测可用，再运行。原生调用内部位置和 usage 仍由该工具管理，客户端不能声称掌握其全部费用。

| 有效合成任务 | 人工确定答案 | 最终结果 | 验收 | 阶段调用 | 本次耗时 |
|---|---|---|---|---|---|
| 三方案按成本≤60、延迟≤50ms 比较 | B | B | passed | 原生规划 1 + 本地提取 1 + 原生推理 1 + 原生验收 1 | 114.0 秒 |
| Python 变量依赖：17 + 7×8 | 73 | 73 | passed | 同上，共 4 次 | 118.0 秒 |

两题均形成两个执行步骤：端侧整理先完成，后续步骤读取其结果并保留原资料，最终验收再核对原文。这两题实际选择 `source → both`，没有为了展示省 Token 而强制丢弃原文；仅依赖输出的交接分支另由确定性夹具验证。

本轮另跑过一题答案 42 的代码流程，但资料注释包含人工答案。它只作为流程检查，不计入上述有效推理验证；已补跑不含答案提示、数值不同的 73 用例。原记录保留，不覆盖。三个实际任务共 12 次阶段启动；上述两道有效用例合计 8 次。报告分别位于 `tmp/collaboration-live/report.json` 和 `tmp/collaboration-live-clean/report.json`，启动脚本为 `tmp/collaboration-live.py`（`--clean` 对应补跑）。

这些用例说明本轮实际交接流程能够完成已知任务，不构成大规模准确率或生产可靠性的统计证明。原生 Harness 未报告完整用量，本轮没有进行完整云端单次基线对照，**不能据此宣称整流程费用节省或超过此前质量门槛**。先前六十题报告保持原结论。
