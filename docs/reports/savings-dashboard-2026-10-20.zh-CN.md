# 累计费用看板与运行反馈

日期：2026-10-20。依据 [用户确认的实施方案](../plans/savings-dashboard-and-progress.md) 完成。本轮仅调整显示与用量记账，不修改模型路由选择、解析/抽取、验收与质量门槛；没有提交 GitHub。

## 用户可见变化

- 首页大字显示累计输入费用节省、减少的输入 Token、已计入操作与统计起点；金额很小时保留足够小数。额外开销使用不同标题与颜色，不能把负值截成零。
- 可展开查看价格、已报告输出、未知用量、历史覆盖范围及统计口径。累计统计暂不可用时显示未知状态，避免沿用旧金额冒充当前值。
- 主任务运行显示当前阶段、已耗时、运转图标和等待进度条；不伪造模型完成百分比。取消中和断线恢复有专门文案，完成、需复核、失败或取消后停止动画。
- 高级单次调用、预处理与文件解析也有等待提示。手机主按钮整行显示，减少动态效果设置会关闭动画。历史查看仍与当前运行任务分开。

## 费用口径

使用官方 [GPT-6.1 Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol) 的 Standard 文本价格，核对日期为 2026-10-20。未缓存输入为 $2/百万 Token；单次输入超过 272K 时该请求全部输入按 $4/百万 Token。缓存输入 $0.10、输出 $10/百万 Token 在详情作参考，不用于编造未知输出节省。

金额仅表示**可见输入优化的参考费用估算**，并非真实账单或整流程净账单节省。所有可比较输入使用同一操作自己的 tokenizer 与消息封装；主任务所有阶段、修正和已知路由回退尝试都计入。失败/取消/未通过验收没有正基线，已知输入开销保留。Harness 内部未知调用、不可确认的旧记录和缺失历史不硬算为收益。不将全部本地推理 Token 当成减少的 Token，也不将本聊天或隔离评测报告导入个人累计。

价格使用 Decimal 计算，SQLite 以整数微美元保存，逐次请求判断长上下文门槛后累计。统计账目独立于任务结果，不保存提示词、结果或密钥。任务 ID 去重；主流程复用已有 `RuntimeConfig.save_run` 完成接入，无需更改 TaskRun 的编排逻辑。保留的历史记录首次按可确认字段补录，随后重启与清理历史均不会重复累计或清空账目。

`GET /api/config/savings` 使用现有本机/会话保护，输出数值汇总、价格与覆盖范围。新装且没有历史时显示真实空状态；本轮检查未找到可恢复的用户运行数据库，没有填入虚构的历史节省。

FreeToken 参考依据为本机安装包 `server/stats.py` 中累计输入/输出字段及供桌面折算费用的接口说明。未取得可核实的 FreeToken 桌面截图，因此参考其累计费用思路与信息层级，不声称像素复刻；未修改 FreeToken 代码。
