2026-10-24T00:18:24+08:00。**完整记录，仍为评测版。**

## 优先问题与结果

此前原生回放的 14 个正确候选被拦截，其中 7 个参考答案错误、7 个参考无效。本轮将北邮 API 限定为选路，复杂执行与独立参考核对使用所选 Harness 的已绑定模型；原答案不被参考建议覆盖。

**固定小批中，14 个原先误拦截的正确候选有 13 个通过。** 剩余 1 个在 API 调度阶段耗尽输出预算，原候选保留。12 个真实错误候选没有被放行，其中 10 个得到有效独立参考拒绝，另 2 个在调度阶段失败，不计作成功识别错误。本地模型调用为 0。

小批仅做 API 分配和固定候选的盲核对，没有重新生成这 26 个候选；不能将 13/14 换算成旧 60 题的整体通过率。前轮是 gpt-6-luna，本轮沿用桌面已绑定的 gpt-6-astra，不能把变化单独归因于路由算法。

## 当前处理方式

- 本机程序解析、统计和确定性查表；有确定性答案时仍可零模型调用结束。
- 北邮 DSv4 API（deepseek-v4-flash）只返回复杂度、Harness、简短理由、本地操作类型。原任务、首行和结构统计用于选路，全部原文留给执行和复核。
- 程序构造执行步骤，调度模型不向执行器灌入猜测答案。复杂/不确定路线禁止本地模型，执行与盲核对在不同上下文中使用已绑定的 Harness 模型。
- 首版自动调度支持 Codex 隔离文本模式；Claude/DSH 未被宣称具备同等文本隔离，文件工具任务继续使用显式角色入口。
- 原有预算、取消、恢复、严格参考检查、候选保留及保值格式整理保持有效。API 输出无效不自动重试或交给本地小模型凑结果。

## 适配开发记录与成本

两次开发实现中止记录全部保留：第一次完整分工计划出现 1536 输出预算耗尽；第二次添加非思考 JSON 请求后仍有截断，因此最终缩小为四字段选择和结构摘要。最终实现的固定小批只运行一次，没有挑选较高分的试跑充当结论。
