# 下一版资料与配置可靠性

- 复用现有解析入口，支持 UTF-8 与带 BOM 的 UTF-16、UTF-32。严格解码，遇到无效文本要求重新导出 UTF-8。记录编码供验证，提升解析缓存版本以重新读取旧缓存。
- 在字节解析入口统一检查 20 MiB 上限与扩展名。文件路径入口采用有界读取，避免文件在检查大小后增长导致无界读取。缓存键改为增量计算。
- 配置保存的读取、验证与更新使用同一 SQLite 写事务，避免并发更新不同字段时覆盖新设置。连接密钥保留判断也放入写事务。
- 用编码样例、损坏文本、大小边界、并发修改验证。运行现有源码和界面回归，打包后用 UTF-16 文件执行北邮云端规划、执行和复核。
- 验证通过后提交 GitHub，合并主分支并发布 EXE、SHA256SUMS.txt。公开下载完整校验。
