# 累计费用节省看板与任务运行反馈

日期：2026-10-20。状态：用户已明确确认“按此方案实施”，现已实施并完成验证。本文件为实施依据。

## 需求与完成标准

首页醒目呈现使用 TokenFlow 以来已记录的输入 Token 减少及其费用折算，采用用户指定的 GPT-6.1 Sol 标准计费；参考 FreeToken 的累计输入/输出与费用展示思路。任务运行时持续显示当前阶段、耗时和运转提示，避免只有静止结果框。

完成标准：金额来源可解释、重复轮询不重复入账、重启/清理任务历史不抹掉累计值、额外输入开销如实抵扣；桌面与手机均能看到节省金额和运行状态；主程序、页面回归与新版 EXE 冒烟通过。此次不改变模型效果、路由、验收门槛或生成样本，不提交 GitHub。

## 已核实事实与复用调查

- 官方 [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) 页面：Standard 每百万文本 Token，输入 $2、缓存输入 $0.10、缓存写入 $2.50、输出 $10。单次输入超过 272K 时整个请求输入/缓存价格乘 2，输出乘 1.5；Fast/Ultrafast、Batch/Flex 和地域另有价格规则。本版默认 Standard、未缓存文本价格，标明来源与核对日期，不冒充实际账单。
- 本机 FreeToken `server/stats.py` 已有累计 `prompt_tokens_total`、`completion_tokens_total`，供桌面计算本地运行的云端等值费用；这些进程内计数会随模型服务重启归零。本项目不直接复制该计数，也不把全部本地推理 Token 当成减少的 Token。未取得可核实的桌面界面截图，不声称逐像素复刻。
- `task_orchestrator.py` 已有原文执行消息基线、所有阶段输入估算、提供商 usage、分角色计量、完成状态和阶段记录，可复用。`estimated_input_difference` 只比较云端输入，不能直接用作全部调用的累计净收益。
- `runtime_config.py` 已有 SQLite 连接、任务记录、请求回执及历史清理，缺少独立于任务历史保留策略的累计统计。当前进程配置所指的用户数据库不存在，没有可确认的早期使用量。后续只能补录实际可恢复的历史，不把离线夹具或评测报告作为个人累计使用量。
- `tokenflow.py` 已有受回环与会话保护的配置接口、实际模型/Harness 调用及预处理预览入口。`ui_page.py` 已有首页、状态条、任务轮询、取消、历史查看和断线恢复，可直接扩展。
- 现有测试为主程序 `--self-check`、`eval_workflow.py --self-check`、`scripts/test_ui.js` 和 `scripts/smoke_exe.ps1`。无需新增前端框架、图表或计费 SDK。

## 显示与统计口径

### 1. 累计 Token 优化费用折算

- 首页大字显示“累计输入费用节省（估算）”，相邻显示累计减少的输入 Token、已记录任务数、统计起点和价格依据；金额足够小时保留更多小数，避免有节省仍显示 $0.00。
- 统一以同一次操作、同一 tokenizer/消息封装下的原文输入和实际发送的所有可见阶段输入比较。主任务的规划、分类、执行、验收、修正和再次验收都计入，不只减云端调用。
- Standard 未缓存折算函数按单次请求输入规模处理 272K 门槛。使用 Decimal；小于等于门槛按 $2/M，大于门槛按 $4/M，基线与各阶段分别计价后求差。
- 只在成功完成的可比较操作中赋予原文基线；失败、取消或未通过验收不能获得正收益。已知额外调用开销保留，净额为负时改为醒目的“累计额外输入开销”，不截成零。无法可靠比较的旧记录或调用列为未计入，不补成节省。
- **本版累计金额只折算输入 Token 的净减少**。输出 usage 和官方 $10/M 输出价格在详情中独立展示，不假定“原文模型本来会输出多少”，不虚构输出节省，也不称为整流程实际账单节省。缓存、工具费、隐藏 Harness 调用及订阅实际费用未知，不能硬算入该金额。
- 累计账目放入现有配置数据库的独立统计表，只保存数值、入口类型、时间和去重标识，不复制提示词、结果或密钥。任务 ID 去重；重复保存/轮询不重复累计，清理任务结果不清空累计统计。
- 真实主任务及可完整比较的单次模型/Harness 调用接入统计；预处理预览不计入已发生收益。不可完整计量的调用保留“未计入”状态。历史补录仅使用字段齐全、口径可确认的实际用户记录；显示已记录范围，不能承诺恢复不存在或已经删除的数据。

### 2. 首页布局

沿用现有深色和浅绿配色、侧栏及工作台。首屏顺序为：

```text
TokenFlow / 任务控制台
┌ 累计输入费用节省（估算） ──────────────────────┐
│ $金额（最大字号）     已减少 Token / 已记录任务 │
│ 自统计起点以来 · 按 GPT-6.1 Sol Standard 折算   │
│ 价格依据与计量范围（可展开）                    │
└──────────────────────────────────────────────┘
任务与资料                   结果与验收
布置任务 / 取消               本次用量与候选记录
当前阶段 · 已耗时 · 等待动画
```

手机单列显示，金额、单位和来源不横向溢出。统计加载、空记录、负值、未知范围和接口失败都有明确文案，不使用装饰性假数据。

### 3. 运行反馈

- 主流程提交后立即显示运转符号、等待进度条、当前阶段和已耗时；实际阶段由现有 `stages/calls/status` 推导。
- 不伪造模型完成百分比。阶段可跳过或进入修正，进度条表示仍在处理，阶段文案表达真实工作；不显示会提前跑满的 99%。
- 完成时停止动画；需复核、失败、取消分别显示明确终态。取消中显示正在等待当前请求结束。断线显示恢复提示，不重置耗时或重提任务。
- 刷新后从已保存任务时间恢复耗时；查看历史时仍保留当前运行任务身份，不干扰现有取消/返回运行任务逻辑。定时器结束时清理。
- 使用可访问状态文字与 `aria-live`，尊重减少动态效果设置。单次高级调用/文件解析的等待提示可复用同一轻量显示组件，不额外引入任务队列。

## 能力与文件边界

- `runtime_config.py`：独立数值账目、任务去重/补录及累计读取；小型 Decimal 定价函数与记录验证也放在此文件，不创建单用途服务层。
- `task_orchestrator.py`：完成主任务后提交已有计量结果；所有调用及终态保持原语义，不改规划/验收逻辑。
- `tokenflow.py`：增加受现有保护的 `GET /api/config/savings`；接入实际请求统计及必要的已知/未知用量信息，不将预览当真实执行。
- `model_providers.py` / `freetoken_provider.py`：只在实际入口需要时保留现有响应中的 usage/尝试信息，以免路由回退被误算为一次调用；不改模型、请求内容或路由顺序。
- `ui_page.py`：累计看板、价格/范围详情、本次用量、进度与耗时，以及各状态的响应式样式。
- `test_savings.py`（新增）、`scripts/test_ui.js`、`scripts/smoke_exe.ps1`：金额、去重与持久化，以及运行/取消/断线/历史等必要回归；主自检接入新检查。
- README：记录折算口径与范围。
- 保持不变：文档解析、OCR、检索/压缩、样本和质量门槛、密钥保护、Harness 绑定与执行权限。现存无关交付目录、用户文档不修改。

## 轻量接口

- `input_cost(tokens) -> Decimal`：Standard 未缓存文本输入的参考费用，检查非负整数及单次长度门槛。
- `record_savings(id, numeric_record)`：内部调用，明确来源/状态/比较口径；同 ID 幂等，仅保存数值与必要元信息。金额不由浏览器传入。
- `savings_summary() -> dict`：累计输入基线、全部阶段输入、净减少、美元折算、已计入/未计入数量、统计起点及官方价格说明。无资料时返回真实空状态；异常不假装有节省。
- 页面运行状态由现有任务响应得到，不增加伪百分比后端字段或额外模型调用。

## 实施与验收顺序

1. 独立验证定价和账目：零值、正值、负值、长上下文、重复任务、重启与历史清理；缺字段不误计收益。
2. 接入主任务与实际调用，验证辅助阶段和失败开销不会漏算；预览、状态读取和轮询不累计。
3. 接入首页与进度组件，检查提交、执行、验收、修正、取消、断线、恢复、历史查看及终态；桌面与 375 像素手机视口截图验收。
4. 运行主程序/评测/UI 回归、编译和差异检查，构建独立新版 EXE 并完成冒烟；本轮不需要重跑数百次模型评测。
