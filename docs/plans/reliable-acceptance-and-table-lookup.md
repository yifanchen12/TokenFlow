# 下一版：可靠验收与本地查表

日期：2026-10-15。状态：2026-10-20 用户已确认全部实施。本文件是实施依据。基线为当前工作区及 [已完成的验证报告](../reports/reliability-2026-10-15.zh-CN.md)，上一轮实现尚未提交 GitHub。

## 需求与完成范围

下一版优先修正任务工作流中的无效验收、无依据修正及重复模型开销。保留原文验收和调用预算，将能明确验证的表格查值交给现有本地工具。单次抽取已有 60/60 正确和 41.62% 总 Token 节省的证据，本版不重新改写抽取算法。

实现验收与模型效果分别记录：实现必须通过定向回归和现有检查；模型目标沿用现有门槛，实测未通过时继续标为失败，不通过降低标准或取消验收取得节省。

## 已确认的依据

| 观察 | 含义 |
|---|---|
| 单次原文/抽取后均 60/60 正确；完整流程只接受 46/60 | 先检查新增验收和修正路径 |
| 7 个验收输出未通过 JSON 解析，2 个验收达到 1024 输出上限 | 需要固定结构和简短输出；单纯增加输出上限会增加开销 |
| 3 个代码题最终答案正确，验收仍为失败；理由还承认答案正确 | JSON 合法不代表判断正确，不能只修输出语法 |
| 5 个任务发生修正，修正后的最终答案有 2 个不符合标准答案 | 需要记录修正前后候选，不能将修正自动视为改进。原始候选未保存，现有资料不足以断言这 2 题都是“改错了” |
| 修正和再次验收共 10 次调用、13497 Token | 有实际收益空间，需要判断何时有充分理由修正 |
| 全部验收输入为 133560 Token，一次原文全部输入加输出为 122422 | 本组任务只改 JSON 格式无法解决全流程成本，必须同时减少可被本地工具替代的调用 |
| 10 个查表题用了 20 次模型调用、90019 Token，约占流程总量 39.8% | 任务是明确的行键和列名查值，优先本地完成 |
| 日常保存连接走普通 Chat Completions；评测的固定上下文和关闭思考走 Ollama 原生路径 | 需要让明确选择的本机 Ollama 连接在日常任务与评测中使用一致参数 |

具体表格题为“表格中 TARGET 的 available 数量是多少？只回答数字。”，输入为包含 `record/items/reserved/available` 的 TSV，目标行唯一。实现不能写死这些字段名或答案。

## 能力与文件边界

### 1. 明确的本机 Ollama 连接与结构化输出

- `model_providers.py`：在现有原生聊天请求增加可选、受控的输出 schema；继续保留完整文本检查、截断失败和 usage。
- `runtime_config.py`：增加显式本机 Ollama 协议，复用 `/v1` 地址和模型发现。普通兼容连接保留原语义；旧连接不自动换协议，避免影响已有 Harness 绑定。
- `task_orchestrator.py`：规划、验收使用各自的小型输出 schema；任务角色输出上限和上下文使用已有策略。验收理由及问题数量/长度有界，客户端仍检查结构与字段一致性。
- `tokenflow.py`、`ui_page.py`：协议列表增加“Ollama（本机）”；任务与高级单次调用复用同一原生适配器，保留各入口已有的输出上限规则。
- `eval_workflow.py`：使用相同适配器和实际参数记录，保留旧命令兼容性，不做仅在评测中生效的格式修复。

明确选择的原生连接只允许回环地址。其他协议不盲目携带其未声明支持的格式参数；不支持能力时给出明确错误，不静默切到远端或不受约束的结果。

### 2. 分离候选回答、验收意见与修正记录

- `task_orchestrator.py`：验收输入分别编码原文、候选回答、任务标准和解析警告；不把它们与输出 verdict 混在一个待回答文本中。保留原文，省去与当前验收无关的派生统计。
- 验收失败需要具体问题及可核对的原文/候选证据，才能触发现有的一次修正。缺证据、结构无效或无法形成具体修改要求时，保留候选并标记需复核；不通过关键词猜测把 `passed=false` 改为通过。
- 修正提示明确最终输出仍须遵守用户要求，验收 JSON 只是修改依据。修正前候选、修正后候选和各自 verdict 均保留；修正失败不抹掉原回答，也不自动宣布原回答正确。
- `eval_workflow.py`：分别统计首个候选正确率、验收后的正确完成率、修正改善/退化数；记录阶段错误类别。JSON 无效的错误提示说明发生在规划还是验收，避免验收失败却提示“未执行计划”。
- `ui_page.py`：仅在存在修正时提供原回答和修正结果的查看，沿用当前运行结果区域；旧记录无这些字段时仍可读取。

自动修正依然最多一次，仍受原有调用与 Token 预算约束。证据存在只是允许核对和修正的条件，不保证模型语义判断正确。

### 3. 明确查表在本地完成

- `task_orchestrator.py`：复用 CSV/TSV 读取与表头、行列一致性检查，支持明确行键和列名的单值查询；查询词和表格内容保持通用，不绑定样本中的 TARGET 或 available。
- 仅处理窄范围的单步明确查询。行键唯一、列名唯一且目标值可用时，按用户要求返回该值，使用确定性验收，模型调用为 0。
- 重复键、缺列、多个工作表存在歧义、模糊语义或混合推理任务不猜测取第一项。目标公式无缓存、目标值缺失时保留警告/需复核，不能作为完整正确结果通过。
- `test_reliability.py` 或现有本地工具回归补充主路径、重复键、缺列和公式缺缓存；继续复用现有文件解析夹具。

这里减少的是不必要的模型执行与验收，不关闭其余推理任务的原文验收。

### 4. 用实际结果验收整条流程

- `eval_workflow.py`、`test_optimizations.py`：核对阶段错误、候选轨迹和全部用量；失败和修正仍计入，未报告 usage 仍未知。
- `scripts/generate_eval_cases.py`：保留旧 60 题作回归；另建不同模板族的 60 题合成保留集，覆盖查询措辞、字段与格式变化、近似键干扰及冲突规则。标准答案仍由规则直接得到。正确/错误候选、重复键、缺列和缺值通过定向夹具验证，不为有歧义的数据强设唯一数值答案。
- 旧集已参与分析和后续调试，不能继续当作独立泛化证据。新模板集也仍是开发者设计的合成证据，真实任务样本继续使用已有人工标注入口。
- 先对旧集完成单次与全流程回归、新集离线保留验证，再运行新集同模型对照。沿用 `qwen3.5:9b`，调用前检查模型和资源，正式计时期间不并行构建。

### 保持不变的部分

`document_parser.py`、`local_ocr.py`、`tokenflow_store.py` 的解析/OCR/检索策略；密钥保护、回环和会话验证、请求回执、取消与保留策略；Harness 权限与绑定协议；现有分类质量门槛。上一轮统计/PDF/历史修复保留，不再次重构。

## 轻量接口与约束

- `ConnectionClient.chat(..., context_window=..., response_schema=None)`：显式本机 Ollama 连接可复用原生能力；非支持协议遇到显式能力请求给出明确错误。返回仍是现有文本与 usage 结构，不改变调用者的响应读取方式。
- `TaskRun.review(...) -> acceptance`：通过、需复核、格式失败明确区分；只有实际通过的结果才能显示为完成。旧 `issues/reason/status/method` 展示语义保留，新增证据与候选字段按需读取。
- 本地查表函数接收任务与原资料；返回确定性答案及行/列依据，或“不适用/无法确定”。不引入全文语义置信度猜测。
- 候选记录只增加有界回答、verdict 和错误类别，不重复保存全套提示词或原文，不把凭据写入报告。
- 所有新字段均允许旧历史缺失；不增加旧任务哈希或版本相等锁。若最小 schema 在本机模型不受支持，先报告实际限制，不伪装格式约束已启用。

## 实施顺序与验收

1. 独立完成原生结构化请求、verdict 检查和本地查表，先用隔离夹具验证；至少确认一条正确与一条错误候选的本机结构化响应。
2. 组装候选/验收/修正流程及预算；确认无效 verdict 不通过、缺证据不触发修正、正确的数值回答不被验收元信息覆盖，旧候选可查看。
3. 接入协议配置、任务入口和评测，验证旧连接、Harness 绑定和旧历史兼容。
4. 运行以下既有检查，并加入上述少量定向回归：

   ```powershell
   python tokenflow.py --self-check
   python eval_workflow.py --self-check
   node scripts/test_ui.js
   ```

5. 旧 60 题中明确查表的 10 题目标为全部正确且 0 模型调用；整体按原有门槛核对完整对比、各类正确率、输入与总 Token 节省。增加新模板组后独立报告，失败不剔除。
6. 页面桌面/窄屏检查、独立 Windows 构建和 `scripts/smoke_exe.ps1` 验证，最后更新报告与校验文件。

模型目标为原有门槛实际通过，包括完整对比与每类 10 对、正确率至少 90%、下降不超过 2 个百分点、输入及总 Token 至少节省 5%。这需要实测，不承诺仅靠 schema 就能达到。代码回归通过与模型门槛通过分别展示。
