# 独立参考核对与安全修正

日期：2026-10-23。状态：用户已明确批准实施。本方案对应用户“进行下一版”，聚焦上一轮报告中的验收误放和修正退化。

## 需求理解与完成标准

明确数字或 JSON 输出的任务，由复核模型先依据原任务与完整资料独立作答，再由程序比较候选与参考值。复核不再只给一个通过标志。没有可确定依据的语义改写作为建议展示，保留原答案；能够证明数值或 JSON 内容未改变的格式修正可以自动完成。

完成指代码接入、真实连接验证、独立评测版 EXE 和结果报告齐备。质量门槛仍为现有标准；若未通过，应记录失败，不能把本轮工程交付称作已实现高可信复杂任务自治。

## 复用调查

- `task_orchestrator.py`：复用 `TaskRun.review_input/review/review_reservation/role_call/execute`、调用预算、完整原文、候选轨迹和重试快照。现有 `source_quote in source` 只证明引用存在，不能证明修正正确；自动修正会覆盖当前结果。
- `answer_checks.py`：复用明确数字输出识别、有界 AST/Fraction 四则运算、程序与近似语义排除规则；增加参考结果与候选的一致性检查，不执行模型代码。
- `eval_workflow.py`：已有严格 JSON 读取和递归比较，拒绝重复键、非有限数、极端指数及过深嵌套。将可共享部分移入 `answer_checks.py`，保留评测入口和现有评分含义。
- `ui_page.py`：已有验收标记、候选记录和过程视图，可在现有位置展示参考差异、当前采用项与未采用建议。
- `eval_scenarios.py`：已有三组对照、错误放行/误拦截和修正退化计量，继续使用；不降低准确率或用量门槛。
- 项目根目录无依赖清单；现有能力通过标准库和可选依赖工作。本轮无需新增依赖。

## 能力与文件边界

1. 结构化参考核对：`answer_checks.py` 承担严格数值/JSON 比较、有限计算与字段绑定；`task_orchestrator.py` 承担参考输出契约、角色调用与状态转换；`eval_workflow.py` 复用相同严格 JSON 语义，保持原评分规则。
2. 安全修正与结果选择：`task_orchestrator.py` 保留原答案，取消依据纯模型错误意见自动改写语义内容的执行调用；只允许内容等价的格式整理。引用和预算不足、参考冲突、字段/算式无效时均保留候选并标记待复核。
3. 过程展示：`ui_page.py` 和 `scripts/test_ui.js` 展示当前采用答案、未采用参考建议及检查范围，保持复制净答案与历史回看一致。
4. 验证和文档：`test_acceptance.py`、`test_scenarios.py` 及确受新契约影响的编排/恢复测试更新；`eval_scenarios.py` 增加参考冲突、格式整理和建议保留的分类计数；README 中英文说明新边界，新增本轮报告。

保持不变：原生隔离执行器 `native_text.py`、连接/密钥配置、价格与累计节省计量、任务路由策略、文件执行权限、文档解析器、个人文档、`deliverables/`。保留旧 EXE 与所有旧评测记录。本轮不推送 GitHub。

## 接口与不变量

### 结构化参考

- 范围：任务明确要求单一数字，或明确要求 JSON 输出。普通说明文继续使用原有模型复核契约；其语义改写同样只保留建议。
- 输入：`user_task`、完整 `original_source`、用户优先的完成标准与解析警告。结构化复核输入不包含候选、执行步骤答案或此前复核建议，减少照抄和锚定；角色、模型与工具禁用规则沿用现有配置。
- 输出对象：`reference_answer`（字符串，按任务给出完整数字/JSON）、`reason`（简短说明）、`source_quotes`（有界原文引文数组）、`calculations`（有界计算数组）。计算项包含 JSON 路径 `path` 和纯数字四则 `expression`，空路径指整个数字答案；JSON 路径使用 RFC 6901 转义规则，只定位既有数字字段。
- 校验：严格类型、大小和深度；引文须实际存在；引用不存在的路径、重复路径、布尔冒充数字、错误算式、计算结果与参考字段不一致均不放行。计算只用现有有界解释器，不使用 `eval/exec`，不调用系统工具。
- 本地比较覆盖完整答案。JSON 键顺序可不同，数组顺序、字段集合、数值和类型须一致；数字使用有界精确值比较，不通过浮点近似放行。
- 程序语言、取整和近似语义不套用有理数算式证明。缺少计算覆盖或来源选择本身未被确定性验证时，明确标为模型核对/局部一致性检查，不标为本地正确性证明。
- 候选与参考相同且检查有效：模型独立核对一致。两者不同、输出不完整或契约无效：保留原答案并进入 `needs_review`，记录具体差异，不自动采用参考值。

### 格式整理与建议

- 只接受能证明内容等价的整理，例如移除完整 JSON 外层代码围栏；数字整理必须能够确定原输出只有一个完整数值，且整理前后精确值一致。不能唯一确定或存在重复字段/无效 JSON 时不整理。
- 格式整理走本地处理，不消耗新的语义改写调用；整理后仍需按原任务核对。不会借“格式修正”改变数字、编号、单位换算或 JSON 值。
- `candidates` 保存实际答案与格式整理版本；独立参考作为验收参考/建议单独记录，不冒充已执行修正。回执记录当前采用项及原因。
- 缺字段的旧回执仍可展示。复制净答案与最终 `result` 一致；界面把未采用建议明确标注出来。
- 预算、取消、使用量和失败调用继续经过现有通道。模型重复一致、引用存在和算式自洽分别只是各自范围内的证据。
