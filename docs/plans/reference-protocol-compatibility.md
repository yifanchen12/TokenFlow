## 需求理解与完成标准

先让现有独立参考协议能被 qwen3.5:9b 稳定使用，并在相同候选上衡量误拦截变化。完成范围为相关代码、接口试跑、条件满足后的固定候选回放、源码与 EXE 验证及报告。整体质量未达到既有门槛时仍为评测版。

本轮不重构整个任务分配器，不增加模型调用轮次，不自动采用参考答案，不降低既有完整评测门槛。

- `task_orchestrator.py/REFERENCE_SCHEMA、review_input、role_call、review`：现有结构化输出约束及盲核对通道可直接调整。当前要求先生成答案，再解释和计算；字符串未约束最小长度；取整任务仍可能生成计算数组。
- `answer_checks.py/exact_arithmetic_context`：已有代码、浮点、取整、近似语义排除；未覆盖已观察到的“只统计完整箱”。只补充明确语义，不用输出为数字推断任务简单。
- `eval_scenarios.py`：已有首次正确、正确完成、误拦截、错误放行、调用及用量统计；复用现有计量，增加可定位的参考错误分类。

- 根目录无 requirements.txt、pyproject.toml 或 setup.cfg；现有标准库能力足够，本轮不增加依赖。

## 能力与文件边界

1. 简化生成负担：`task_orchestrator.py` 调整提示与 schema 的生成顺序，先来源和最终字段算式，后简短理由和完整答案；补充短小的数字/JSON 示例。暂保留四字段字符串答案协议，避免引入新的数据迁移和递归序列化器。
2. 明确算术适用范围：`answer_checks.py` 修复明确完整份数、完整箱数等向下取整语义的误识别；`task_orchestrator.py` 根据本次任务与原文选择计算数组约束。原文只影响语义分类，不能修改系统规则。
3. 定位失败：`answer_checks.py` 区分空答案、理由不合规、引用无效、重复路径、字段不存在、算式不一致和覆盖不足；`eval_scenarios.py` 汇总分类。`ui_page.py` 在现有验收位置展示简短中文原因，不展示内部堆栈。
4. 配套验证：扩展现有测试，增加 `scripts/check_reference_protocol.py` 用于固定小批协议试跑和固定候选回放；保存脱敏报告与独立产物。

重要保持不变：`native_text.py`、连接和密钥存储、原生隔离、模型选择、任务路由、价格及节省统计、样本评分、语义修正禁用策略、个人文档及 `deliverables/`。旧报告、原始评测数据和 EXE 均保留。用户随后追加要求：完成后提交并推送 GitHub。

## 接口与不变量

- 参考输出继续为 `source_quotes`、`calculations`、`reason`、`reference_answer` 四字段对象，JSON 键顺序不影响读取，历史回执可继续展示。`reference_answer` 仍是完整数字或 JSON 的字符串。
- schema 与运行时检查共同拒绝空白答案、缺失字段、错误类型、重复路径、无效引用及不受支持的算式；不能依赖 schema 代替运行时验证。
- 单一数字的精确算术任务只允许一个空路径算式，算式必须表示最终结果，不能把多个中间步骤都绑定空路径。JSON 任务仍要求所有数值字段有且仅有一个绑定算式，字符串编号不参与计算。
- 明确涉及取整、程序或近似语义时，`calculations` 必须为空数组；该分支仅做独立答案比较和来源引文检查，界面明确未完成算术证明。不把识别不到的复杂语义擅自改成普通除法。
- `reference_schema(task, source)` 只生成本次输出约束，由复核调用使用；不改变 planner/executor 的 schema 或权限。原生模型沿用相同文本协议，响应仍经过相同校验。
- 复核输入仍只有原任务、完整原文、语义标志与解析提示，不包含候选、规划答案或旧参考。候选与参考不同/参考无效时保留原答案，不增加修复或仲裁调用。
- 对外 `error_code=invalid_reference` 保持兼容；`reference_error` 提供有限、可统计的失败分类，错误消息不拼接原文或敏感配置。
- 引文存在、字段算式一致、两个模型答案一致均不证明来源选择或全局最优正确。
