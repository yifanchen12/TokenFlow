# 2026-10-15 六项修复实施计划

用户已以“全修”确认 [下一版分析](../reports/next-version-review-2026-10-15.zh-CN.md) 的六项范围，并选择先检测本机 Ollama `qwen3.5:9b`，可用时进行同模型评测。

## 复用与边界

复用 Decimal、现有 XLSX/PDF 解析、RapidOCR、阶段预算、SQLite 历史、同模型评测和现有页面控件。不增加依赖，不改变提供商密钥保护、原文验收要求、请求回执和 Agent 权限。

1. `task_orchestrator.py`：按输入位数/指数范围及行数计算有界 Decimal 精度；精确求和与中位数，均值不能有限表示时显式标记舍入。超范围拒绝，不以错误结果通过。
2. `document_parser.py`、`task_orchestrator.py`、`ui_page.py`：保留公式警告和缺缓存信息，传递文件解析元信息到任务。缺数值的统计保留部分结果但为 needs_review；计数任务不因无关的公式缓存警告失败。上传文本仍保留公式占位和解析提示，不假装重算公式。
3. `document_parser.py`：结合图像区域与已有文字密度判断混合 PDF；复用本地 OCR 补足有遗漏风险的页面，保留原有文字并按行去重。缺 OCR 时明确失败/警告，不能静默丢正文。更新解析缓存版本避免复用旧结果。logo/文字完整页不无条件 OCR。
4. `task_orchestrator.py`：复用同一阶段消息构造和估算，首次模型调用前检查验收最低上下文；规划后/每个执行步骤前预留后续验收需求。输出实际长度仍受现有预算检查，不能承诺 Harness 内部用量。
5. `task_orchestrator.py`、`eval_workflow.py`、`ui_page.py`：原文基线使用与执行同范围封装，补充分角色输入/输出及已报告用量明细。完整流程评测使用本地 Ollama 原生 API 的固定上下文、温度 0、关闭思考；原文与各阶段参数一致。先少量检查，再 60 题合成保留集；真实门槛不通过时如实报告，不调低标准。
6. `runtime_config.py`、`tokenflow.py`、`ui_page.py`：在现有历史接口增加有界分页、任务文字搜索与状态筛选。SQLite 以 updated/id 作稳定排序，默认仍返回最近 20 条；按 ID 读取和活动任务跟踪独立于筛选。页面使用原生输入/选择/按钮，沿用现有响应式样式。

## 接口约定

- `local_statistics` 保留现有字段，增加数值覆盖/缺失公式/精度说明；对计算范围错误返回明确安全错误。无法完整计算的确定性任务不走模型猜测补数值。
- 解析结果增加/保留 `warnings`、未缓存公式数量、PDF 页 OCR 元信息。路径任务与上传任务应有一致提示。
- 预算预检和实际调用复用提示词构造。已知不可行时零模型调用停止，动态输出仍在下一阶段前检查。
- `RuntimeConfig.runs(identity='', *, limit=20, offset=0, query='', status='')` 保留 `runs` 并返回分页元信息。limit 为 1–100、offset 非负且有上限，query 有长度上限，状态白名单；HTTP `/api/tasks` 接收对应参数并继续会话保护。
- 页面的分页不改变 activeRun/viewedRun；搜索结果为空时显示原因，过期响应不得覆盖当前筛选。

## 实现与验证顺序

1. 独立实现并验证 Decimal、公式/PDF 元信息、历史查询；仅使用隔离夹具。
2. 装配统计验收、预算预检及计数明细，重跑分析中的错误复现。
3. 接入 HTTP 和页面，用 Node 回归及桌面/窄屏预览检查分页、筛选、运行任务恢复和解析提示。
4. 运行主自检、评测自检、120 合成/60 仓库资料保留检查、语法/差异检查；构建独立 Windows EXE 并冒烟检查。
5. 若本地指定模型可用，先运行少量同模型流程检查，再完成 60 题保留集单次及完整流程对比。评测使用临时配置，不改用户策略，不下载模型或调用远端。

## 验收标准

大整数相消为 1；均值舍入可识别；公式缺值的部分统计不通过；混合 PDF 保留图片正文和页脚；无法容纳验收的已知任务零调用拒绝；计数口径一致；25 条以上记录可完整翻页与筛选；既有回执、取消、保留策略和 UI 状态回归通过。

真实模型评测反映实际效果，即使节省或准确率门槛失败，也不以模拟结果替代。模型不可用时记录检测结果，先完成全部修复及离线验证。
