# 端云协同任务分配与使用体验

状态：已完成，2026-10-20。替代专用 Python 构建方案。验证见 `docs/reports/edge-cloud-collaboration-2026-10-20.zh-CN.md`。

## Requirement reading

用户澄清：本轮要优化 TokenFlow 的体验和分配，让产品可以端云协同处理复杂任务。编译是可能的任务场景，本轮核心是协同调度、交接和可理解的执行过程。

完成范围：明确端侧与云端的职责和可用性；按步骤依赖交接必要资料；展示实际分工、中间结果和失败原因；在既定预算内处理端侧失败；保留原文验收及真实用量。先在现有最多四个顺序步骤内完成，不引入新的代理框架、任意 shell 执行或专用编译器。

## Reuse survey

- `task_orchestrator.py` 已有本地统计/查表、上下文选取、分类摘要角色、规划器、执行器、验收器、计划校验、调用与 Token 预算、一次有证据修正、取消、任务锁和提交回执。
- 现状：本地摘要仅在复杂请求、6000–16000 字符、完整资料不超过 16000 字符等条件同时满足时触发；规划只使用摘要或开头预览；执行步骤重复携带上下文、派生统计与全部既往输出；计划尚无显式依赖和输入范围。
- `runtime_config.py` 已有连接的 `local` 标记、角色/模型、Harness 绑定和持久化设置。分类摘要角色允许显式云端连接，不能因角色名称叫 `local` 就宣称推理发生在端侧。原生 Harness 的实际位置不确定时单列，不虚构为云端。
- `model_providers.py` 和 `ConnectionClient` 已支持保存的模型连接、Ollama 原生协议、usage、失败计量与安全错误。复用，不新增 SDK。
- `ui_page.py` 已有阶段、运转动画、耗时、历史和候选查看；但复杂分工主要显示在文字日志中，用户难以看到步骤产出、依赖和升级过程。
- `docs/reports/acceptance-2026-10-20.zh-CN.md` 已记录旧/新合成集合全流程总 Token 分别增加 4.60% / 14.79%，验收仍有误判。结构合法和多次模型调用不能作为可信或节省的保证。
- 核心使用标准库。复用 `json`、现有 token 计数和测试工具即可。
- 入口与检查：`/api/tasks/start`、`/api/tasks/<id>`、`TaskRun.execute`；`test_orchestration.py`、`test_controls.py`、`test_acceptance.py`、`test_savings.py`、`scripts/test_ui.js`；主程序自检、评测自检、UI 检查、EXE 冒烟。

## Capability and file boundaries

- 分配规则与配置体验：
  - `runtime_config.py`：保存明确的协同策略，复用连接/角色/模型，不迁移或覆盖现有连接密钥。保留原角色配置兼容；端侧只能使用被登记为本机直接推理的连接。
  - `task_orchestrator.py`：增加不调用模型的任务预检与路由说明。检查所需角色、执行位置和预算；本地工具优先，复杂任务由配置的规划/执行角色处理。端侧不可用时说明回退行为；仅本地策略禁止外发。
  - `tokenflow.py`：增加受保护的任务预检入口，复用现有启动、查询和取消接口。
  - `ui_page.py`：提供易懂的协同策略选择和本地/复杂执行连接设置，原四角色等配置收于高级选项；显示将使用哪些连接、哪些信息需要交接及配置缺口。
- 复杂步骤与可靠交接：
  - `task_orchestrator.py`：扩展现有计划结构，增加稳定步骤编号、前置依赖、输入范围和预期产出。顺序执行仍最多四步；缺字段的旧计划兼容原有输入行为。校验依赖只能指向已完成前序步骤，最终步骤必须汇总必要产出。
  - `task_orchestrator.py`：每步保存自己的状态、输入说明、实际执行器、输出和耗时。只携带该步骤要求的原文/抽取内容及依赖输出，不再机械拼接所有历史。摘要作为辅助线索，不能代替原文证据或随意删除数据。
  - `task_orchestrator.py`：端侧整理失败保留错误，回退已有确定性上下文；计划内端侧模型步骤失败时，只有策略允许、配置明确且预算足够才升级一次到配置的复杂执行器。验收预算优先，失败重试也计入开销。云端/原生执行器失败保留中间结果并停止，不自动重跑整个任务。
  - `task_orchestrator.py`：最终验收继续核对原文，保留有证据的一次修正。模型未完成、验收无效或未通过时，不能标为完成；中间产出明确标注为部分结果。
- 过程、结果和验证：
  - `ui_page.py`：在现有进度与结果区域展示步骤清单：谁在做、依赖什么、当前状态、耗时、实际输出和升级原因。区分最终结果、部分结果和待复核；保持刷新恢复、取消、历史切换及手机可用性。
  - `eval_workflow.py`：报告保留实际分工、步骤依赖、升级、各阶段与全部用量，支持核对协同是否减少重复输入。失败和验收开销保留。
  - 新增 `test_collaboration.py`：用明确的端侧/云端夹具检查交接、路由、升级、预算和失败保留；现有 UI / EXE 冒烟检查只补相关主路径。
  - `README.md` / `README.zh-CN.md`：说明协同策略、执行位置、限制和结论含义。
- Unchanged：文档解析/OCR/查表算法、PC Agent、安装器、原生 Harness 默认权限、已有样本标准答案、累计费用的参考价格。费用统计只增加必要的新阶段识别，不虚构节省。

## Interfaces and invariants

- 预检返回：策略、已配置角色与实际位置、拟走的阶段、缺失配置、预算约束。预检不产生模型调用、不保存任务、不把缓存模型目录当成当前服务可用的保证。
- 每次任务保存策略快照。仅本地策略不能调用云端连接或位置未知的原生 Harness；协同策略只使用用户已配置的目标，不能悄悄新增提供商或更换模型。
- 计划步骤增加 `id`、`depends_on`、`input_scope`（原资料、前置产出或两者）、`expected_output`。新旧格式明确校验；未知工具、越序/循环依赖、空交接和无法汇总的计划拒绝执行。
- 步骤输出保存于 `step_results`，与最终 `result` 分开。取消、失败和预算不足保留已完成步骤；没有最终产出时 UI 不把最后一个中间步骤当成最终答案。
- 本地模型辅助整理只在预计有实际用途且有预算时调用。整理输出可用于规划和定位资料；事实依据仍来自原文。统计和查表仍可零模型调用完成。
- 所有升级、修正和失败调用进入现有预算及用量统计。输入不完整或 Harness 内部用量未知继续明确标注；不能用漏计调用制造费用收益。
- 原文过大而不能完成既定验收时明确提示容量/预算限制，不擅自把部分材料标成完整验收。
- 页面展示执行地点依据连接配置和实际记录，不依赖模型自述。不展示密钥；不把模型输出直接作为 HTML 插入。

## Build order

1. 在现有模块中独立验证策略预检、依赖校验和步骤输入组装。使用确定的夹具检查输入隔离、兼容旧计划及预算边界。
2. 组装任务流程，验证端侧整理、复杂执行、一次升级、原文验收和中间结果持久化。此时先不修改页面。
3. 接入预检 API、配置和页面。验证同一任务的实际分工与步骤展示一致，刷新/取消/历史不会串任务。
4. 增补评测报告；运行少量明确标为合成的复杂任务端到端验证。真实模型结果与夹具分开，不用离线响应冒充模型能力。
5. 完成现有回归、桌面与窄屏检查、EXE 构建和冒烟，交付报告。

## Validation

- 文档提取 → 比较 → 汇总：端侧输出传给确有依赖的复杂步骤，最终结果保留原文依据。
- 代码资料/故障日志分析：不同执行器完成准备与推理，实际位置、输入及各步输出可核对；不宣称已经实际编译代码。
- 无端侧连接、端侧失败、仅本地策略、调用预算不足：不能静默外发、超预算或丢失部分结果。
- 越序/循环依赖、未引用必要步骤、无效规划或验收：拒绝错误完成；旧计划和旧历史仍可读取。
- 前端预检、步骤面板、取消/刷新恢复、窄屏布局；主程序自检、评测自检、UI 回归、语法检查、EXE 冒烟及 `git diff --check`。
- 模型验证沿用现有连接和模型，先检测本机服务。端云真实对照需要实际可用的云端连接；不可用时如实报告，不能将两个本地模型称为端云验证。

## Open questions

- 沿用用户已有连接及模型，通过界面选择职责；不预设新的云端供应商。实施时核实当前配置与服务，遇到影响真实验证的缺口再询问。

## Facts vs assumptions

- Verified：用户要求优化端云协同体验与分配；现有顺序编排、角色和进度可以复用；当前额外调用与重复输入存在实测成本。
- Assumed for approval：本轮以现有四步顺序任务为边界，先完成可见分工、有效交接与有界升级；专用 Python 构建执行器留作后续场景接入。
