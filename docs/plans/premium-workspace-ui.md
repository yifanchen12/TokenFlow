## Reuse survey

- `ui_page.py` 已内嵌全部 HTML/CSS/JS，有侧栏、费用概览、任务提交、进度、步骤、连接配置、缓存管理和历史。当前三个样式块多次覆盖相同选择器；结果显示在历史、指标和步骤之后，主要区域信息密度较高。
- 复用 `renderSavings`、`renderRun`、`renderProgress`、`renderStepBoard`、`orchestrateTask`、历史恢复、取消和配置保存，保持控件 ID 和请求字段兼容。
- `scripts/test_ui.js` 已有 DOM 夹具和实际页面函数测试；`scripts/smoke_exe.ps1` 验证打包页面和原有功能；PyInstaller 从 `ui_page.PAGE` 打包，继续内嵌资源即可，无需新前端框架或额外静态文件服务。
- 使用原生 `dialog`、按钮和标签页语义；系统字体、内嵌 SVG 图标和现有数据足够，无新增依赖。
- 入口：`/` 页面和现有任务/配置 API。检查：主程序自检、评测自检、UI 回归、语法、桌面/手机检查、EXE 冒烟及 `git diff --check`。

## Capability and file boundaries

- 视觉与信息结构：`ui_page.py` 整理为统一样式，保留深色墨绿识别；重整侧栏、顶部运行状态、累计节省与主工作区。收紧次要状态信息，主按钮和最终结果获得明确视觉优先级。
- 配置体验：`ui_page.py` 将现有连接和存储设置收进原生设置抽屉，保留已有字段与高级角色分配。关闭按钮、Escape、键盘焦点和手机滚动完整可用。
- 结果体验：`ui_page.py` 提供“结果 / 执行过程 / 任务记录”视图，最终答案及验收状态优先；过程保留真实进度、实际地点和各步产出；历史筛选保留。加入复制当前结果操作，使用文本写入，空结果时禁用。区分模型复核与确定性校验，不提升验收证明范围。
- 验证与交付：`scripts/test_ui.js` 补充设置开关、视图切换、复制与原任务恢复回归；`scripts/smoke_exe.ps1` 补新界面存在性检查；README 与新报告记录交互、截图及最终 EXE。
- Unchanged：`task_orchestrator.py`、`runtime_config.py`、模型适配、解析/OCR、所有 API、调度权限、原文验收、预算和费用口径。不借视觉升级修改后端策略。

## Interfaces and invariants

- 现有控件 ID、会话头、请求回执和 localStorage 恢复语义不变。只保存必要的界面状态，不将任务资料写入浏览器存储。
- 设置抽屉由显式按钮打开；原生对话框管理焦点，关闭后返回触发位置；手机采用可滚动全屏布局。
- 标签页具有选中态和键盘操作；隐藏内容不改变任务状态。轮询不会覆盖用户查看的历史或强制切换视图。
- 模型输出与复制内容始终作为文本处理，不使用未经清理的 HTML；不为样式引入远程脚本、字体或统计请求。
- 金额、调用次数、耗时和状态只使用现有真实数据。负节省、未知用量、失败、需复核和部分结果都有清楚的文字状态。
- 手机无横向溢出，输入至少 16px，主要交互触控至少 44px，键盘焦点可见，减少动态效果偏好有效。

## Build order

1. 整理独立的页面视觉和设置/视图交互，用现有隔离记录检查空、成功、运行、失败等状态。
2. 将既有渲染和轮询接入新区域，验证历史、取消、刷新恢复和费用显示一致。
3. 验证实际页面与原 API 后再构建 EXE，完成桌面/手机截图、冒烟及第二次 GitHub 提交。
