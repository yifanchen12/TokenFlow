## Capability and file boundaries

- `runtime_ownership.py`：共享 OS 文件锁与存活判断；供服务、任务互斥及运行记录保护复用。
- `runtime_config.py`：统一活跃记录判断；提供只在内存持有密钥的固定运行配置；旧配置和历史继续可读。
- `task_orchestrator.py`：固定本次连接和绑定、数据库任务互斥、范围明确的静态 Python 数值求值、准备/规划决策记录、可恢复的步骤输入与只读产出复用。重试生成新任务，使用新回执、预算和用量，不覆盖旧结果。
- `static_python.py`：仅解析有界、无副作用的整数表达式及无参函数依赖；不执行源码，不识别不支持的 Python 为已验证。
- `tokenflow.py`、`launcher.py`：服务实例所有权、已有实例反馈、受保护重试入口；原生执行器复用固定配置。
- `eval_scenarios.py`、`eval_workflow.py`、样本生成器：单次原文、原文执行加验收、真实端云流程的成对对照与分角色统计；单独记录合理拒答，原正向门槛保持。
- `ui_page.py`：固定可见的进度/执行者/耗时/取消、恢复失败任务、净答案和完整结果复制、设置对下次任务生效提示。查看历史时不抢焦点。
- `test_lifecycle.py`、`test_static_python.py`、相关现有测试与 `scripts/test_ui.js` / `scripts/smoke_exe.ps1`：仅增加上述行为所需的跨进程、快照、预算、恢复、文本及 API 回归。
- README 和新验证报告：如实交付实现、模型实测、质量门槛、截图与最终 EXE。
- 保持：解析/OCR、检索事实保护、价格、PC Agent 与任意命令权限不扩大。

## Interfaces and invariants

- 同一个配置数据库的服务与任务分别使用原生进程锁；运行记录不能仅因 PID 不同而被判死或删除。
- 活跃任务调用读取固定的配置视图；设置修改用于后续任务。密钥仅在内存和原有受保护连接中，不进入运行记录或评测报告。
- 本地静态求值只接受明确的单值查询与支持的 AST；不支持、歧义或有副作用的代码回退既有流程。原文和标准答案不由模型改写。
- 恢复只复用已完成的只读步骤，原资料必须仍可读取；有可能产生文件副作用的 Harness 步骤不自动复用。新任务保留旧任务关联和复用说明，但不把旧调用再次计费。
- 调度中所有实际调用、失败、修正和升级均计入原预算。无完整 usage 不报实际费用收益。固定进度不显示虚构百分比。
- 正向评测保持原门槛；应拒答集合独立检查，不能以合理拒答放宽正向正确性要求。

## Build order

1. 独立验证进程锁、固定配置及静态求值；把两处研究复现改为回归。
2. 组装编排、预算、恢复和评测统计；用明确夹具验证依赖复用和三种对照。
3. 接入服务与工作空间，验证预检、重试、历史、复制和滚动进度。
4. 检测并沿用已有本机 Ollama / 原生连接，先做小开发集，再跑保留集及原有回归；保留失败门槛和未知用量。
5. 完成主程序/评测/UI 回归、桌面/手机验证、EXE 构建及冒烟，交付结果。

## Validation

- 两个进程同库：运行记录不可误删、不能并发启动；真实退出可恢复/中断，独立数据库不互相阻塞。
- 运行中改 API 连接与原生绑定：当前任务固定，新任务采用新值，公开输出无密钥。
- 静态整数求值：不同名称、嵌套依赖、负数与运算、循环/动态/危险结构拒绝，超限不求值。
- 已完成准备步骤＋失败最终步骤：恢复不重跑准备，重试与取消仍受预算限制，原资料缺失或副作用步骤不能静默复用。
- 三种对照完整/缺失 usage、负收益、拒答与失败计入；原有同模型模式仍可用。
- `python tokenflow.py --self-check`、`python eval_workflow.py --self-check`、`node scripts/test_ui.js`、语法与差异检查、桌面/手机与 EXE 冒烟。
