## 目标与完成范围

本轮围绕“资料选取和质量判断是否可信”开展四项工作：合成样本、检索完整性、Python 依赖保留、评测判断。验收以复现问题消失、原有检查继续通过和结果来源清楚为准。运行耗时、模型正确率及实际 Token 收益需要后续模型对比数据，不能从离线检查推断。

不扩展模型提供商、数据库框架、界面布局或 Agent 工具权限。真实任务导入及人工确认流程保持现有约定。

## 四项能力及文件边界

### 1. 可复现的合成样本

- 新增 `scripts/generate_eval_cases.py`：由种子、模板参数和独立的规则计算构造资料、关键事实与正确答案；不以模型回答作为正确答案，不调用网络。
- 建议首批 120 题，六类各 20 题：长文位置变化、历史与现行规则冲突、表格结构、代码依赖、资料内干扰指令、文件解析。开发集与保留集各 60 题，每类各 10 题；按模板族划分，避免仅替换数值后复用同一模板。
- 保留集用于后续回归观察；合成模板和分布仍由开发者设计，不称为真实业务泛化证据。
- JSON 使用现有 `task`、`content` 或 `source_file`、`must_keep`、`expected_answer`、`answer_match`、`category`；固定 `source_kind=synthetic`。附加 `seed`、`template`、`split` 仅用于理解样本来源。
- 生成资料包括文本及小型 DOCX、XLSX、PDF、PNG。格式依赖缺失时明确列出未生成项目；不能将跳过项计为通过。先采用小而稳定的版式，不构造无法独立核验答案的开放式任务。
- 增补 `eval_workflow.py` 的来源分类报告，确保混合输入时合成、仓库问答、真实任务的质量与收益分别呈现。
- 修改 README 中的生成、离线检查和模型对比说明。输出默认放入被忽略的 `tmp/synthetic-eval/`，不混入个人资料。

### 2. 检索保留分散证据

- `tokenflow.py:compact_content`：检索结果可以帮助定位，但不能把其他明确词法命中排除。保留全部命中的完整范围；范围过大则沿用原文回退。
- `task_orchestrator.py:TaskRun.select_context`：沿用当前文档限制和缓存，来源描述应覆盖实际选取范围；前三条可以作为展示预览，不能称为完整证据列表。
- `test_optimizations.py`：加入多处规则、后置更新事实和跨块命中复现，确认现行与历史事实均保留，或明确回退原文。
- 不调整数据库模式或搜索后端。压缩率降低可以接受；不能为提高压缩率删除已命中的关键资料。

### 3. Python 抽取保留直接依赖

- `tokenflow.py:compact_content`：复用现有 AST，在保留函数/类时补充其可静态解析的模块级常量、导入和直接辅助函数；处理依赖链和循环，避免无限展开。
- 对无法可靠解析的动态查找、嵌套依赖或复杂写入，采用保守回退。达到原有范围上限时同样回退，不提高上限掩盖问题。
- `test_optimizations.py`：覆盖全局常量、辅助函数、循环引用和超限回退。只解析合成源码，不执行用户代码。
- 其他语言沿用现有行为；不引入通用依赖分析框架。

### 4. 评测拒绝假通过，并覆盖真实选取路径

- `model_providers.py`：统一验证“输出完整且非空”的判断，安全错误只带归一化 usage。`evaluate`、原文流程基线和编排调用复用这一判断；保留现有 Responses/Messages 截断处理。
- `runtime_config.py`：适配器归一化时保留 Messages 的结束原因，并拒绝 Responses 非完成状态/待续工具调用及无效结构，供共享检查判定。实现时确认旧归一化丢失结束原因，需在此调用入口补足，而不是只改评测。
- `eval_workflow.py:evaluate`：截断、空答案、无效结构不进入完整答案对比；已产生的 usage 和失败原因继续记录。区分模型请求失败与答案不正确。
- `eval_workflow.py:summarize`：每类沿用整体最低正确率及允许下降阈值，新增每类最小完整对比数（建议默认 10）；不足则标为未评测，类别失败阻止整体通过。报告保留现有整体指标，并列出类别判断及原因。
- 增加明确的离线任务资料选取模式，例如 `--offline-task-context`：使用隔离数据库运行解析、索引、检索及 `TaskRun.select_context`，不调用 `TaskRun.execute` 或任何模型。默认单次提示词模式保持现有入口行为。
- 离线模式只证明资料/标注保留，不给模型正确率或实际用量填零，也不能把质量门槛标为已通过。
- `.github/workflows/checks.yml` 增加生成样本及实际选取路径的离线检查；延续已有 60 题仓库基线和 Windows 构建验证。
- `scripts/smoke_exe.ps1` 增加打包程序的 Python 全局常量保留检查，继续通过本地预览接口验证，不调用模型。
- `test_optimizations.py`、`test_controls.py` 加入截断拒绝、类别全部失败、类别样本不足、不同来源分别统计和两种选取模式的必要分支。

保持不变：连接密钥保护与协议配置、真实样本人工确认要求、预算及请求恢复契约、PC Agent 权限、OCR 引擎、个人 deliverables 和现有私人配置。

## 接口与错误约定

- `generate_cases(seed, split)` 输出可被 `load_cases` 和 `_validate_case` 接受的样本。相同模板版本及种子输出相同；无正确答案规则的模板不能入集。输出不覆盖已有人工资料。
- `compact_content(content, task, matched_spans)` 保持当前签名、标记和原文回退行为；检索范围不能删掉已有明确命中，源码选取不能仅保留未定义的直接依赖引用。
- 统一的响应检查返回完整文本或安全 `ProviderError`；输出上限导致截断时仍保存可用 usage，调用次数照常计入。
- `summarize` 返回现有 summary/quality_gate，并添加来源分组及类别门槛结果；失败优先于未评测，未知数据不能变成通过。
- 离线任务上下文模式的所有缓存位于临时目录，不读写用户策略、历史或原始文档缓存。与模型参数冲突时提前报参数错误。

1. **独立样本与响应检查**：实现规则生成器及完整响应验证；验证生成样本结构、正确答案计算、固定种子稳定性和截断 usage 保留。

3. **模块装配**：让实际任务选取、评测和来源/类别判断使用同一套规则；验证整体 90% 而某类 0% 时不能通过，截断答案不进入完整对比。
4. **入口与 CI 接入**：接入生成 CLI、离线任务上下文入口和文档；运行两套语料的必要回归，再完成 Windows 构建检查。
